# 人物显示与近战（当前：四方向 2D）

## 2026-10-29：正式显示改为四方向 2D 贴图

- `Assets/Characters/dwarf.json` 的 `Renderer` 现在为 `sprite4`。居民、敌人和头像使用 `Assets/Characters/Sprites4/`，普通游戏不再实例化旧人物网格、骨架或 AnimationPlayer。3D 场景保留为历史资源及战斗采样数据的来源。
- 男女基础形象来自用户给出的男女三视图，使用 imagegen 生成透明绘画素材；本版两种基础身均保留参考图的米白背心和短内裤。每种形象有正面、右侧、背面三张图，左侧镜像；按镜头坐标判断四方向，静止保留朝向。不是 Blender 渲染帧。
- 每帧格子 256×384，三格横向图集 768×384，脚底 y=368，人物高度约 352 像素对应 1.4 米。穿戴支持布衣、裤子、靴子、手套、皮帽；铁剑、矿镐、锻锤、铁斧、战斧、铲、锄、盾牌使用独立手持贴图。盔甲/铁盔素材仅作为后续扩充备用，尚未新增游戏物品或配方。
- 衣物按组合合成并缓存，角色通常只绘制身体、手部遮挡和两件手持物；左右手遮挡随方向变化。图像资源共用，缓存最多 64 种服装组合。未做大规模人群性能基准，不能据此给出 FPS 保证。
- 简单动作包括行走/搬运起伏、工作挥动、攻击挥动、举盾/招架、倒地。全部由模拟时间驱动，暂停冻结。身体使用整张纸片，尚无逐帧四肢动画，双手工具也没有单独的双臂握持姿势。
- 近战数值和碰撞仍使用原有模拟、武器配置及采样轨迹；2D 武器动作是状态示意，不保证画面像素与扫掠轨迹逐点重合。不要为纸片摆动重新烘焙旧骨架数据。
- 外观档案新增 `BodySex`（male/female）；旧存档缺省 male，新居民可随机男女。外观窗口只显示当前贴图支持的男女选项；原肤色/发型等字段保留兼容，不再显示不起作用的选择器。
- `bash source/tools/sprite-demo.sh` 打开可暂停、换装、换动作、切换男女及旋转镜头的四方向演示；加 `-- --record-sprites` 输出 10 秒演示帧。`--sprite-integration-test`（兼容旧名 `--dwarf-integration-test`）在当前渲染配置下检查男女读档、装备卸装、镜头方向、暂停、攻击及实际行走，并保存营地截图。
- 生成提示词与原始图集：`art/dwarf/sprites4/prompts.json`、`*-source.png`；确定性的裁切/图集打包脚本：`pack_sprites.py`、`pack_clothes.py`。最终预览：`art/dwarf/sprites4/demo.mp4`。

## 模型交付

- 推荐导出 GLB，保留源文件。游戏 1 单位＝1 米，矮人脚底到头顶 1.4 米；原点在两脚之间的地面。
- 导入后的模型 +Y 向上，正面朝 -Z；Blender 可正常导出，朝向差异通过配置 YawDegrees 补偿。Scale 默认 1，不自动猜模型尺寸。
- 共用骨架、原地动画；不要把人物前进位移写进根节点。移动、楼梯和坠落由模拟决定。
- 手部骨骼下挂 BoneAttachment3D，下面放 Node3D，分别命名 MainHandSocket、OffHandSocket。武器场景根变换负责调整握持位置；盾牌挂左手。
- 一个角色场景包含一个 AnimationPlayer；动画名在配置中映射。人物场景应为展示资源，不附带自行移动、自动播放或碰撞伤害脚本。
- 衣服与身体使用同一骨架，头发胡须可拆分。第一阶段尚未实现三维衣服替换、肤色和脸型映射；头像继续使用纸片形象。
- 优先少材质、共享贴图，暂不使用布料和胡须物理。需用实际多人场景测 FPS，不能用单人模型表现推断性能。

## 接入配置与已实现范围

历史 3D 制作配置在 source/Assets/Characters/legacy-model3d.json（以下为旧方案记录）：Scene 填 res://Assets/Characters/dwarf.glb（或含骨骼挂点的包装 .tscn）。空路径保留现有纸片；文件不存在会警告并回退。配置在进程中缓存，修改后重新运行。

Animations 将语义状态映射为实际动画名，支持带库前缀的名称。idle、walk、combat_idle、work、attack、down 已接状态；block_raise、block_hold、block_hit、block_break、hit 只预留命名，尚未接入防御状态机。

EquipmentScenes 示例：`{"sword":"res://Assets/Characters/sword.tscn","shield":"res://Assets/Characters/shield.tscn"}`。没有对应模型则不显示该三维装备，不自动把图标当作武器。装备场景缺失不影响库存与战斗。

居民与敌人共用 ActorModelView；采用模拟时间采样动画，暂停时姿势不前进，继承楼层和迷雾隐藏。沿路径和攻击目标转向；模型脚底不沿用纸片上下摆动。选择胶囊、姓名、目标标记与头像保持独立；暂保留旧 Sprite3D 作为头像来源和回退兼容层。

目前 attack 由旧战斗的 Strikes 事件驱动，仅用于模型联调，仍然是旧命中率结算，不是挥剑接触伤害。不能依靠动画方法回调直接伤害目标。

## 第一批动画

先制作 idle、walk、sword_shield_idle、sword_slash、block_raise、block_hold、block_hit、hit、down。随后补收盾、破防踉跄、被格挡回弹、后退与侧移。完整交互成立后再加多方向攻击。

盾牌流程：举盾→保持→接触受震→恢复或破防→放盾。防御有生效时间；来袭轨迹必须先接触盾牌才挡住身体，不能朝后也自动挡。持盾攻击是否保留防御由招式覆盖范围决定。

## 下一阶段：权威攻击轨迹

每招定义起手、有效挥击、收招时间，以及体力、伤害类型、可打断阶段、武器轨迹和格挡反应。轨迹从动画采样导出，与显示共享时间轴。

固定模拟步推进，渲染插值。剑刃采用线段或胶囊，扫掠相邻时刻之间的区域；曲线需要有界子采样，不能仅检查端点或把弧形简化成一根长直线。身体先用头、躯干、肢体简化体；盾牌用薄盒。按最早接触处理盾、墙、身体，一次攻击对同一目标只伤害一次。命中后由护甲和部位结算伤害，不再额外随机判成未命中。

格挡需要有效阶段、来袭方向、盾牌交点和体力；不足则破防。受阻后使用明确的终止/回弹规则，避免穿盾继续命中身体。多人交战要明确友军阻挡规则。楼层、高差和墙体参与空间判定。

性能：仅有效挥击时查询附近空间格；不做全体两两检测，也不使用逐三角形碰撞。动画不可见时仍须模拟攻击轨迹，FPS 不得影响 TPS 结算。未来加入可见性与距离动画分级；当前只跳过楼层隐藏模型的姿势采样，尚未完成屏幕外/远距离 LOD。

存档需记录招式、攻击阶段时间、目标及已命中集合，暂停/倍速/读档不能重复扣血。当前档案仍使用原战斗格式，待攻击状态机落地再迁移。

## 后续武器

匕首：短刺/横切；双手剑：斜劈/下劈/直刺；长矛：平刺/上段刺；钉头锤：斜砸/下砸。分别使用刃、尖端、锤头判定区，不仅更换武器图标和数值。双手握持与近身退步后续单独适配。

## 通用近战判定第一阶段（已接入）

以下取代上文“近战仍为原命中率结算”的旧状态说明：主游戏现已接攻击起手、有效挥击、收招、接触判定、主动盾挡与限时招架。正式盾挡/招架/破防动画仍未交付，显示临时复用 Carry 的固定姿态，因此防御代理形状尚不是最终美术网格的精确碰撞。身体也使用简化胶囊，不做逐三角形碰撞。

### 扩展入口

`Simulation/MeleeProfiles.cs` 中武器定义独立包含：动画名、起手/挥击/收招时长、攻击距离、碰撞半径、伤害类型/数值、体力与冲击、是否可招架、招架消耗/准备时间/时间窗/防御距离。盾牌独立包含宽高厚度、相对身体位置、举盾时间、消耗与承受冲击能力。判定代码不以“是不是剑”决定伤害或防御类型。

已提供单手剑、匕首、双手剑、长矛、钉头锤、锻锤、矿镐和徒手的配置，以及木盾、小圆盾、大盾模板。**只有当前物品表已有的装备可在游戏里使用**；新增武器/盾牌模板不等于已经加入生产配方、物品、模型和动画。新增类型还需注册 ItemCatalog/ResidentGear，并提供相应轨迹与外观。当前一把武器只有一个基础攻击，未做连招、双持和横扫多目标。

剑使用 `Assets/Combat/sword-trajectory.json`，由 `tools/bake-melee.gd` 从第二版男模型 Attack 动画和右手挂点采样，60 Hz 记录剑刃两端。改动画/剑长后应重新烘焙；女版及其它体型仍需单独校准。攻击姿态会旋转到让偏离身体中线的剑刃瞄准目标；攻击期间锁定方向，不持续追踪躲开的目标。其它武器模板暂用参数化刺击/挥击轨迹，不能声称其未提供的动画已同步。

### 判定与防御

- 起手不伤人；有效阶段以最多 10 ms 子步采样轨迹，剑刃沿长度约每 6 cm 做相邻时刻扫掠，同时检查整条剑刃重叠。属于有界近似扫掠，并非精确连续网格碰撞。
- 只查询附近空间桶内的人物与轨迹包围范围内的实心方块/关闭闸门；墙、地板和武器轨迹使用同一世界高度。楼梯/斜坡的细分碰撞、门扇动画和家具碰撞尚未细化。
- 身体按头、躯干、双臂、双腿简化，接触部位决定伤口，命中后不再掷一次未命中骰子。护甲负责部位减伤。
- 每次攻击只处理第一次有效接触。盾挡/招架、墙体、友军都能截断这次攻击；第一版友军阻挡但不受伤，不自动穿透友军。
- 盾挡需面向来袭方、举盾完成、轨迹接触盾牌代理盒。盾牌不再作为全身被动护甲。背后攻击可绕过盾牌。
- 招架需持有可招架武器、准备完成、处于短时间窗且轨迹接触防御武器的简化胶囊；不能空手永久招架。
- 盾挡和招架消耗体力。体力不够会破防并短暂不能防御/攻击；这次拦截仍耗尽来袭攻击，后续攻击利用空档。无攻击/防御时恢复体力。
- 攻击/撤退命令切换、解除征召、换掉攻击武器和失能会取消当前攻击；保留短恢复时间，避免取消动作刷攻击。

防卫面板的“主选防御”可选自动、优先盾挡、只用招架、不主动防御，并显示主选人物的体力。它只作用于主选居民，不冒充整组选项。自动模式在观察到目标起手后选盾挡或招架，尚不是复杂战术 AI。

### 时间、存档与测试

模拟持有 AttackWeapon/AttackTime/锁定方向/是否已接触、防御阶段、体力及反馈；模型直接读取 AttackTime，屏幕外也照常判定。存档升级至 16，兼容旧档默认状态，并验证新增字段；已处理接触不会因读档再伤害一次。同一模拟步内按稳定角色 ID 顺序处理，不宣称同时互杀的连续物理求解。

`navigation-check.sh --melee-checks` 检查起手、命中、移开挥空、中途筑墙、盾前后方向、破防、招架时间窗、空手不可招架、友军截断、取消、疲劳、盾牌不被动减伤、存档与非法数据、不同步长。`--combat-checks` 继续覆盖原撤退、多人跨层、医疗与战斗闭环。`--melee-test` 用真实模型检查模拟/动画时间一致及盾挡结果，并截图至 `.local/melee-windup.png`、`.local/melee-shield.png`。

本轮验证结果：构建零警告/错误；新增近战测试与原战斗回归通过；真实模型专项通过并检查截图。24 人/12 次同时挥击的 30 个模拟步，近战子系统总计约 7–9 ms，单步峰值约 3–4 ms（本机专项测量，不代表整局 FPS/TPS）。自动招架等待适当时机再打开窗口，避免起手即招架导致窗口在剑落下前失效。

## 装备物理尺寸统一（当前实现）

本节取代前文独立 Reach/盾牌代理尺寸的描述。唯一尺寸来源为 `source/Assets/Combat/equipment-geometry.json`，由 `EquipmentPhysicalCatalog` 读取，`GearDefinition.Dimensions` 和近战配置共同引用：

- `Size`：装备握持坐标系下 X/Y/Z 三轴实际尺寸（米）。剑主要沿 Z 轴；盾牌 X 是横向、Y 是厚度方向、Z 是竖向。不能把三轴名称一概叫宽/高/长。
- `ReferenceMin/ReferenceMax`：现有模型在握持原点下的原始包围盒，用于校准。默认尺寸保持原模型大小；剑全长约 0.745 m，握持原点到尖端约 0.58 m。
- `ContactStart/ContactEnd/ContactRadius`：原始模型坐标下的有效刃、尖端或锤头判定段；随实际尺寸同比缩放。只拉长剑身不会增大横向判定半径。握柄、剑格不自动作为刃伤害区。
- `MaterialId`：类型默认材质标识，只作为未来材质系统入口；未自动影响重量、伤害或价值。

模型按 Size / 原始包围盒尺寸缩放，缩放围绕握持原点进行。单轴加长当前会拉伸该轴上的柄和刃，若要独立改变柄/刃造型，应提供新的校准模型。不会自动猜测替换模型的单位或轴向；真实模型检查会检测原始包围盒变化。

`grip-poses.json` 只保存动画挂点的位置与朝向，不再写死剑刃端点。剑与矿镐的轨迹由挂点变换 × 同一份装备接触段生成。Reach 从有效攻击阶段的实际轨迹包络与判定半径推导，不再手填；用于接近目标与附近查询，是否伤害仍由实际扫掠接触决定，角色身体体积另行参与碰撞。只改装备 Size 后重新构建/启动即可；修改骨骼、握持方向或动作才需要运行 bake-melee.gd 重新烘焙。旧 sword-trajectory.json 不再被代码读取或编译为资源。

盾牌判定盒直接使用同一尺寸定义下的模型包围盒，经过实际防御挂点变换；招架使用该武器的实际接触段，不再另造一个固定长度的“防御剑”。临时 Guard 姿态由生产角色包装脚本生成，两段手臂定位保持骨长，同一姿态供模型播放和离线采样。它仍不是正式的举盾/受震/破防过渡动画。

所有尺寸使用米制，不允许用 ActorModelView 的整体 Scale 偷偷改变角色/武器而不改变判定；该旧显示参数不为当前校准模型提供缩放。新骨架和新朝向需要重新校准挂点。男女第二版的手持资源包围盒和骨骼参考点一致；不同体型不能未经校准复用。

### 材质、品质、耐久接口

每个 ItemStack 和在途 MaterialReservation 新增不可变 `ItemProperties`：MaterialId、QualityId、Durability、MaxDurability。空材质回落到类型定义；默认品质 normal，两个耐久字段均为 null 表示未启用。旧存档自动得到默认属性，版本升级至 17。

属性随拾取拆分、搬运、交付、任务取消落料和存读档保留；只有属性完全相同才可合堆。品质/材质使用稳定字符串 ID，耐久校验有限非负且不超过最大值。**目前不结算磨损、断裂、品质加成或材质加成；即使字段填写了耐久，也不改变战斗行为。** 物品堆中的成员暂时共享同一组属性，未来发生个体磨损前需要先拆分该件物品。
