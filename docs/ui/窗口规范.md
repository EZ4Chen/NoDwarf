# 游戏窗口规范

第一批样板：设置、生产清单、生产清单详情。后续窗口复用这些组件，避免各自复制颜色、标题栏和按钮样式。

## 布局

| 场景 | 结构 | 当前样板 |
| --- | --- | --- |
| 管理窗口 | 标题与右上关闭 → 页签或分栏 → 可滚动内容 → 必要的底部操作 | 设置、生产清单 |
| 详情或编辑窗口 | 标题与右上关闭 → 内容 → 完成或保存操作 | 生产清单详情 |
| 地图检视面板 | 左下信息，旁边排列对象操作 | 后续逐步接入，不改成居中管理窗口 |

资源、时间、天气属于地图 HUD，继续使用无整块背景的样式。

## 公共组件

- `source/Scripts/GameUi.cs`：颜色、字体、间距、按钮、表单行、滚动区和列容器。
- `source/Scripts/GameWindowFrame.cs`：统一标题栏、关闭按钮、内容区 `Body`、状态区 `Status`、底部操作区 `Footer`。
- 外壳可以直接放在地图 UI 下，也可以放进原生 Godot `Window`，不承担玩法或存档逻辑。

颜色集中在 `GameUi`：深灰蓝背景、较深的内容底色、低对比细边框，选中用蓝灰色，主要提交动作使用暗金色。正文 15、标题 20；常规间距 8、窗口内边距 16、控件高度 34。图标按钮使用较小内边距，不能把图标挤成小点。

## 新窗口用法

```csharp
var frame = new GameWindowFrame("生产管理", CloseProduction);
root.AddChild(frame);
frame.FitCentered(root, new Vector2(900, 560));
var scroll = GameUi.Scroll(frame.Body);
var column = GameUi.Column(scroll);
var count = GameUi.Field(column, "目标库存", new SpinBox { MinValue = 1, MaxValue = 10000 });
frame.AddAction("完成", CloseProduction);
```

需要保存的表单使用 `frame.AddAction("保存并应用", Save, true)`，取消按钮写“取消”，并在悬停提示及可访问描述中说明放弃未保存内容。即时生效的编辑使用“完成”，不额外制造一次确认。`frame.SetStatus(...)` 显示结果或错误，空字符串隐藏状态区。

原生 `Window` 内将外壳铺满，设置 `Borderless` 避免双标题栏，可调用 `frame.EnableWindowDrag(window)` 拖动标题。窗口关闭由调用方处理；不要把销毁、保存或取消任务藏进公共外壳。

## 交互与清晰度

- Esc 只关闭最上层窗口，由窗口或宿主统一处理并消费该输入；不能顺带清空底层选择。
- 普通说明放悬停提示。保留表单标签、空列表的下一步提示、密钥保存方式、计费提示、删除后果和显示回退提示。
- 图标按钮必须有可访问名称与悬停说明。输入框、数量框和复选框使用 `GameUi.Field` 保留名称与键盘焦点。
- 内容滚动，标题和底部操作固定；生产详情窄于 900 时改为单列，生产清单窄于 760 时上下排列。
- 不给通用外壳再覆盖一套局部颜色。确需特殊状态，只调整相应组件，新增共用样式时集中到 `GameUi`。

## 验证

`--llm-settings-test` 检查各设置页、560×380 布局、可访问名称、保存、取消、错误处理与显示回退；接口使用本地模拟，不向外部发送请求。

`--production-target-preview-test` 检查真实鼠标操作、配方添加、暂停、排序、删除确认、详情筛选、存读档、640×440 布局和 Esc 的关闭层级。可见窗口运行时截图写入 `source/.local/`。
