# 流体系统：设计与阶段一

更新：2026-10-27。目标是让水流、地下突水、封堵和蓄水成为可操作的玩法。参考《缺氧》的材料与生产联动思路，采用适合三维方块地图的离散模型；不求解连续流体动力学。

## 阶段顺序

1. 水量守恒、重力、横向找平、连通水体水头、有限含水层与补给、蓄水池、手动闸门、水深显示、存档与回归。
2. 泵与管道、热量搬运和低频环境换热。
3. 冰水相变：质量守恒、潜热与部分冻结；薄水不能产生完整冰块。
4. 房间／连通空间级气体，蒸汽、冷凝与通风。
5. 岩浆、地热与魔法流体。

## 阶段一的数据与规则

- 空隙中记录稳定材料 ID、整数水量和热量。满空格 1000 单位，1 单位对应 1 升水；液体与建筑 ID 分开，不把空气覆盖成不可寻路的实体方块。
- 材料表预留密度、比热、冻结／沸腾温度、潜热和相变产物 ID。本阶段只允许水；热量随转移按质量比例搬运，不做环境换热或自动相变。
- 向下优先，横向逐渐找平。满水通道传递水头，允许 U 形管和竖井向上灌水；水头决定可达到的水面，不凭空生成水。
- 三维世界边缘封闭，不默默删除越界水。开发者加水、移除与地下补给分开计账。水深影响通行；不加入游泳、溺水或漂浮物流。
- 方块墙和关闭的闸门不透水。闸门是独立的一米设施，默认关闭；关闭时保留格中已有水，不删除水。普通木门不保证密封。楼梯／斜坡按半格剩余容量近似，暂不做细分几何流动。
- 禁止在已有水的格子直接建造其他实心设施，避免无声删水；后续再加入挤水施工。

## 地下突水

- 含水层用岩层中的有限储水记录表示，具有坐标、容量、当前储量、最大水头、每秒出水上限和补给率。挖通相邻岩石后产生出水口；重新封堵停止出水。
- 水头随剩余储量衰减，低于出口时停止出水。补给是明确的外部质量来源，有速度和储量上限。不同出口共享同一储量与流量预算。
- 新区域地图按种子生成少量隐蔽含水节点，避开出生区地表。旧存档不得凭空增加含水层。第一版不生成巨大地下洞湖，水池可通过挖坑并蓄水形成；开发者可创建有限水体／含水节点进行验证。
- 只显示已知格附近的含水风险，不通过 UI 泄露整张地图的地下资源。

## 计算与表现

- 流体以 5 Hz 更新，与人物 TPS、渲染 FPS 独立；静止区域休眠，开挖／建造／开闸唤醒邻域。
- 流量和连通压力计算均有工作上限；阶段一为单线程确定性处理，后续才迁移为快照计算、统一提交的并行任务。
- 大洪水不能无限占用一个模拟 tick；达到 Demo 容量限制时停止扩散并保留原处水量，显示积压／限额，绝不删除水。性能上限必须写入实现说明。
- 水面用批量网格显示，遵守当前楼层、迷雾和切墙规则；刷新不重建整个地形。选中格显示水量、水深和温度（仅保存与混合）。
- 尚无雨水积累、侵蚀、冲毁墙体、浮力、空气压缩、水锤、蒸汽或相变。地下突水不需要这些机制即可成立。

## 必须验证

- 落水、找平、静池休眠、拆墙唤醒、阶梯容量、边界密封；每一步无负水量、无超容量、总质量守恒。
- U 形通道上涨但不超过水头；断开／关闭通道后压力不继续跨越。
- 有限含水层出水耗尽、补给记账、封堵和多出口共享预算；新种子一致，旧档不追加含水层。
- 热量跟水搬运与混合；暂停、倍速、存读档继续一致；拒绝非法坐标、负数、超容量及不支持的材料。
- 游戏窗口检查可见水面、水深、闸门开关与地下剖切；完整模拟和鼠标交互回归。

## 当前实现与试玩入口

阶段一已实现。核心在 `source/Simulation/Fluids.cs`，世界接入在 `WorldFluids.cs`，显示在 `source/Scripts/FluidView.cs`。满水格作为传压通道，直接在连通通道的水面／出水边界之间转移质量与热量，避免逐格搬水在管道中产生假空气缺口。不是连续压力波或流速场。

每步最多 2048 个活动格和 256 次边界输水；压力连接扫描有全局湿格上限 32768，含水节点上限 128。单次调用最多补算 8 步，其余时间保留为积压；正常 60 TPS 时仍按 5 Hz 更新。闭合水池和封闭边界不会删除水。当前仍为单线程，没有完成最大洪水场景的办公笔记本性能验收。

新地图至多生成 16 个含水节点；旧档不追加。深水（本格 ≥0.5m）禁止寻路；尚无游泳／溺水和救援。普通木门不密封，闸门一格高，可以叠建；开关闸门暂为直接控制。材料 ID 可由现有材质清单替换。

建筑规划的“结构”栏已有闸门及图标；选中后可开关。F1 开发面板可向选中地格注水／排水；F2 的 `aquifer` 命令可构造承压试验。命令格式、限制、日志和截图位置见 `source/README.md` 的“流体阶段一”。存档格式 12 起支持流体，当前格式 13 兼容房间温度。
