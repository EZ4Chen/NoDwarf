# 生物系统框架

2026-10-30；世界存档版本 28，生物子存档版本 1。

本阶段提供配置、实例与模拟接口，不添加正式动物、自动刷新或显示模型。矮人已通过适配层接入共享物种、身体定义、能力查询与统一观察/伤害入口；生活、健康和战斗继续由原系统执行，同一对象只有一份位置和伤势。

## 配置与扩展

默认入口为 `source/Assets/Definitions/creatures.xml`，当前包含 `base:dwarf`，不自动生成野生动物。完整示例位于 `source/Assets/Definitions/Examples/creatures.example.xml`，不会自动加载。使用已有行为添加物种只需 XML，不需要增加物种枚举或分支。

- `Bodies/Body/Part`：任意命名部位、部位生命值、是否致命部位。至少一个致命部位；致命部位归零即死亡，不套用居民的十部位结构。
- `Movements/Movement`：速度（米/模拟秒）、最大上跨和下落高度、梯子许可、可接受水量比例。当前是陆行、单格占地，仍复用居民的保守净空与连接规则。
- `Species/Species`：稳定 ID、显示名称、身体/移动模板引用、行为 ID、思考间隔、种群上限。
- `View`：`none`、`billboard` 或 `model`，资源与材质路径必须是项目内 `res://`，另有显示缩放。此处只是表现描述，渲染器尚未接入；缩放不改变碰撞或净空。
- 根节点 `populationLimit` 限制总实例数量，`updateBudget` 限制每次模拟更新访问的实例数。死亡但未移除的实例也占数量上限。

当前内置 `core:idle` 与 `core:wander`。新的行为由 `CreatureBehaviorRegistry.Register` 注册函数，再由 XML 引用；配置不能执行任意代码。游荡只选择合法相邻格，没有远距离目标寻路。飞行、游泳、大体型、多格占地、生态刷新、进食、驯养与繁殖后续分别实现，不能仅修改一个 XML 属性就假称支持。

默认目录配置在首次访问时加载并缓存，修改后重启。也可通过 `CreatureCatalog.Load(Stream)` 读取完整配置并在空种群上调用 `world.ConfigureCreatures(catalog, registry)`。当前没有模组目录自动合并、热更新或迁移管理器。配置发生语义变化仍需迁移；空白缩进不会改变指纹。

## 接入接口

1. 加载并校验目录配置。
2. 在世界中调用 `SpawnCreature(speciesId, cell, seed)`，验证站立位置和数量上限。
3. 世界更新调用种群 `Advance`。固定预算轮询，按每种生物的间隔决策，不补算积压思考；无生物时不分配种群、不运行生物循环。
4. 表现层以后通过 `Ids()` 与 `Observe(id, simulationTime)` 获取实例和移动插值。快照不暴露可修改的生命值字典；这些读取接口会分配快照，未来渲染器应缓存 ID 并避免每帧复制全部健康数据。
5. `DamageCreature(id, part, amount)` 处理部位伤害；死亡停止移动，保留实例。`Creatures.Remove(id)` 显式移除，当前不自动生成尸体物品或掉落。

行为输出仍经相邻与通行校验；途中路径被阻塞会取消该步。预算只限制访问数量，不隔离注册函数的执行时间；扩展行为也必须有界。目前在模拟主线程执行，野生行为不调用 LLM，不新增后台线程。野生生物之间及与居民之间没有实体避让，野生生物尚未接入居民的攻击目标与护理任务。居民继续使用原有 LLM 决策入口。

## 存档

世界存档保存实例 ID、物种、部位生命值、死亡时间、在途移动、随机状态、思考时刻与轮询游标。旧存档加载为空野生种群，不自动补动物；版本 27 及更早的居民默认物种为 `base:dwarf`，保留现有伤病、需求、工作与战斗状态。恢复在完整校验后才替换种群。

物种与其引用模板的 XML 指纹一起保存。缺失物种或配置指纹改变会明确拒绝载入，避免静默删除动物或重置健康；当前包括名称、外观等修改也会触发此保护，需后续明确迁移策略，暂不支持自动迁移。更改身体模板前应保留原配置和存档。

## 矮人与通用生物（本次接入）

`controller="resident"` 使用居民任务与健康适配器，`controller="wildlife"` 使用基础生物调度器，省略时为后者。控制器是实现模块，不是居民身份，也不是智慧等级。居民控制器物种不能再次通过 `SpawnCreature` 加入野生调度，避免重复实例和重复更新。

`ResidentProfile.SpeciesId` 是物种；是否属于聚落或敌人由现有 `Workers` / `Enemies` 关系决定并随存档保存。相同物种可以出现在两边；能力不由阵营决定。当前尚无访客/招募系统，不能仅改身份标签就完成招募。

能力由物种内配置：

```xml
<Capabilities>
  <Capability id="work" />
  <Capability id="equipment" />
  <Capability id="combat" />
  <Capability id="social" />
  <Capability id="research" />
  <Capability id="care" />
</Capabilities>
```

- `work`：自动普通工作分配。研究与护理工作还检查对应能力。
- `equipment`：穿戴装备；已有健康和双手检查继续生效。
- `combat`：征召和实际近战攻击。无此能力的对象仍可以受到攻击。
- `social`：双方交往能力。
- `research`：开始研究活动，包括手动和 AI 共用入口。
- `care`：治疗、救援及给他人送饭/用品；自己吃饭、喝水和睡觉不依赖这个开关。

矮人默认全部保留。未列出的能力视为不具备；自定义能力 ID 可供后续模块读取，但新玩法仍需实现对应模块。

`world.AllCreatureHandles()` 同时列出居民、敌人与野生实例；`ObserveCreature(handle)` 返回相同格式的物种、社会角色、当前位置、死亡状态、能力与部位完整度。句柄区分存储来源以避免 ID 冲突，`resident` 来源不代表聚落成员。观察值即时读取原对象；`InjureCreature` 对矮人/敌人委托原伤势流程（包含护甲、流血、治疗与后遗症），不会维护额外 HP。野生生物目前只支持基础伤害，不假称已有完整疾病与护理机制。

为避免破坏现有健康公式，居民控制器目前明确要求原来的十部位、每部位 100、头与躯干要害。不同身体结构仍可用于野生控制器，异形智慧生物需要扩展健康适配器。居民的移动、外观与模型保持已有实现；XML 的移动与 View 描述暂不覆盖居民实际寻路与模型。新物种可复用当前人形适配器和能力配置，不能仅改 XML 就获得多肢或飞行功能。

自定义人形物种可设置 `resident.Person.SpeciesId` 后在初始化阶段调用 `world.ConfigureCreatures(catalog)`；载入时将同一目录传给 `DemoWorld.LoadJson(json, catalog)`。默认矮人无需额外调用。不要在已有活动进行中热替换物种；热迁移不是本轮功能。

完整回归（仓库根目录）：

```bash
bash -c 'source source/tools/env.sh; dotnet run --project ../benchmarks/NavigationBench.csproj -- --creature-resident-regression'
```

包含共享实例/伤势/位置、同物种不同阵营、配置能力实际限制、旧档迁移、自定义物种往返和缺失定义拒绝，以及居民生活、健康、护理救援、战斗与近战专项。
